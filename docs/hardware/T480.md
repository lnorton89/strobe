# Test machine: ThinkPad T480 (owner's laptop)

This is the owner's real-hardware test machine and the reference "old
laptop" Strobe is built for. A remote bridge session runs on it
(`DESKTOP-24U41EB`, working copy
`C:\Users\ExaltedLaptop2\Development\strobe`). The coordinating cloud
session drives it.

## Hardware (reported 2026-10-08)

| | |
|---|---|
| Model | Lenovo 20L5CTO1WW (ThinkPad T480) |
| OS | Windows 11 Pro, build 26300 |
| CPU | Intel Core i7-8550U, 4 cores / 8 threads |
| RAM | 31.9 GB |
| GPU | **Intel UHD 620 only** (no discrete GPU, not hybrid graphics) |
| GPU driver | **30.0.101.1122**, dated 2021-11-14 |
| Display | One internal panel, 2560×1440 @ 59 Hz, Windows scaling to 1707×960 logical |

**This driver matters.** Intel UHD 620 on driver 30.0.101.1122 is the
exact combination that rustaman documented taking an access violation
inside `igvk64.dll` (the Vulkan ICD) during swapchain creation. Strobe
doesn't use Vulkan, but this machine is the right place to prove the
WGL path, the ANGLE fallback, and native crash capture (minidumps) on a
driver known to misbehave.

The display is 1440p, so a fullscreen output on this panel means
rendering 3.7 M pixels per frame on an integrated GPU. That makes render
scale and adaptive resolution decisive here, not optional.

## Toolchain and build (2026-10-08, commit 2143d7b)

Rust 1.98.0 on the MSVC target and a working MSVC linker were already
installed.

| Step | Result | Time |
|---|---|---|
| `cargo build --release --workspace` (cold) | OK, no warnings | 2 m 26 s |
| `cargo test --workspace` | OK, 70 tests, 0 failures | 8 s |
| `cargo clippy --workspace --all-targets --all-features -- -D warnings` | Clean | 27 s |

The 7 renderer tests (`crates/strobe-gfx/tests/render.rs`) all **skip**.
Intel's Windows driver doesn't expose EGL device enumeration
(`EGL devices: not found`), so the headless context doesn't exist here.
`strobe-bench` fails for the same reason:

```
Error: headless context: EGL devices: not found
```

**Consequence:** on Windows, the bench and the renderer tests need a
WGL- or ANGLE-backed context from a hidden window. The windowed context
provider exists (`strobe-app`), and `strobe-bench --context window` now
uses it (D70), so the bench runs here. The renderer tests still skip.
