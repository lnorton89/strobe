# D557: the website looks the release up at build and again in the browser, renders its cards with Metaplate, self-hosts its fonts, and states facts instead of selling (2026-11-05, owner's request)

**Context.** The owner saw old version numbers on the live site and took them
for hardcoding. They were not constants: D526 reads GitHub at build time. But
deploys are by hand (D525), so the live site named v0.2.0 a day after v0.3.0
shipped, until someone next deployed. Other things had piled up in the site:

- `next build` fetched three fonts from Google, which failed CI's `site` job once.
- Social cards were route handlers around `next/og`, with no file extension, so
  each host needed a rule for their type, and every subpage lost `og:site_name`,
  `og:type` and `og:url` to Next's shallow metadata merge.
- The copy was built around "stays up on old laptops", called a source-available
  project open source, and carried stale claims (fifteen crates, a screenshot
  caption naming the wrong scene, the status line describing an old release).

**Decision.**

- **The release: both lookups, one module (`site/src/lib/release.ts`).**
  - At build, `scripts/sync-release.mts` asks GitHub, then `git describe --tags`,
    then gives up, and writes `public/generated/release.json`. Pages read that
    file. The build renders in up to eleven worker processes, and each one
    fetching for itself (as D526 did) could name a version on some pages and not
    others when the rate limit ran out part way through. A shallow clone with
    GitHub down still builds; the site then names no number and links to
    `/releases/latest`.
  - In the browser, `components/Release.tsx` asks GitHub once per session per ten
    minutes and replaces what the build wrote: the same pattern and budget as the
    roadmap's feed, one of the reader's sixty requests an hour. Any failure keeps
    the build's answer.
  - Why both: a build-time lookup alone is the problem the owner saw, since it is
    only as fresh as the last deploy. A client lookup alone leaves no version or
    download for no-JS readers and crawlers.
  - Asset names carry the version, so `/releases/latest/download/...` cannot name
    the zip. The download page reads the zip's name, size and checksum from the
    release. URLs are built from a checked tag and asset name, never taken from a
    payload, since the browser's copy passes through sessionStorage.
  - `REPO` in `lib/site.ts` is the slug's one home in the site's code, for the
    repository's possible move. `package.json` repeats it, and a test holds the
    two together.
- **The cards: [Metaplate](https://github.com/freeknet/metaplate) 0.8.2**, from
  npm, pinned exactly.
  - `metaplate render` writes `og-image.jpg` beside each route before the build
    (`scripts/render-cards.mts`, `lib/og/`). No route handler remains, nor the
    `_headers` and `netlify.toml` rules they needed, and no server runs a renderer.
  - `createNodeOg`, not `metaplate/next`, because only the Node renderer has
    render guards and an output encoder. Text off the canvas or with no font
    fails the build.
  - JPEG through `sharp`: half of each card is a real scene frame, as the guide's
    social preview asks (section 7), and as PNG one reached 916 kB, over
    WhatsApp's 600 kB limit. They are now 37 to 123 kB.
  - `version: "copy"` gives a changed card a new URL, since crawlers cache by URL.
  - `lib/og/metadata.ts` is the one way a page states its metadata, so no page
    loses a field to the shallow merge.
  - Metaplate is MIT. Satori and resvg-js, which it brings in, are MPL-2.0. All
    three run only at build and none ships to a reader; `site/README.md` credits
    them. Metaplate's problems found on the way were filed on its repository.
- **The fonts come from `@fontsource`**, already a dependency for the cards,
  through `next/font/local`. They are SIL OFL 1.1, so `sync-assets.mjs` publishes
  each licence at `/generated/fonts/` and `site/README.md` credits them.
- **The copy states what can be checked.**
  - "Built to run on old laptops" and anything like it is gone. The fact is
    engineering: an OpenGL 3.3 core floor, ANGLE on Direct3D 11 as the fallback,
    adaptive resolution, no per-frame allocation or driver queries. It says which
    GPUs were measured, and that no HD 4000 has been.
  - The home page's frame times are read from `docs/BENCHMARKS.md` at build
    (`lib/benchmarks.ts`), which keeps D526's rule against hand-copied numbers
    without losing the numbers. A heading that stops matching fails the build.
  - The feature grid is six plain paragraphs with no icon, each ending on what is
    not verified where that applies.
  - The project is source-available, in those words, wherever a licence is named.
- **Prefetches work on a static host.** Next's client asks for segment data at
  `__next.download.__PAGE__.txt` and the export writes
  `__next.download/__PAGE__.txt`, so every page logged eight 404s on every host.
  `scripts/flatten-segments.mjs` copies each file to the name asked for, after
  the build.

**Trade-off.** The header's chip can change a moment after load, when a newer
release is found. The string is the same width in practice, so nothing moves. The
cards add `sharp`, Satori and resvg to what a build runs, on top of the Next
copy of Satori they replace; none reaches a reader.

**Test.**
- `tests/unit/hardcoded.test.ts`: no version, tag or asset name in the site's
  source; the slug in one place; no "open source" and no selling line in the copy.
- `tests/unit/release.test.ts`: the payload, the lookup order, the failures.
- `tests/unit/cards.test.ts`: every card renders through the guards and passes
  Metaplate's WhatsApp, LinkedIn, Discord and X profiles.
- `tests/e2e/release.spec.ts`: a stubbed v9.9.9 reaches every place that names the
  release; GitHub down, rate limited or empty, and JavaScript off, keep the build's
  answer.
- `tests/e2e/console.spec.ts`: no page logs an error, 404s or reaches a font service.
- By hand on LIGHTNING, a full build against a local stand-in for the GitHub API
  named v9.9.9 in the export; with the API unreachable it named the checkout's tag;
  with git failing too it built and named none.

**Would reopen:** deploys moving into CI on each release (W-03), which would make
the browser's lookup less needed; GitHub tightening unauthenticated API limits; or
a Next release that writes the segment files where its client asks for them.
