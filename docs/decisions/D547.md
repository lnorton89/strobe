# D547: Shadertoy imports go to user-scenes/shadertoy-imports, and thumbnails are rendered for scenes without one (2026-11-04, owner's request)

**Where imports go.** A Shadertoy import was written into the library
folder, `scenes/`, which git tracks and which holds only original work.
An imported shader is someone else's.

- Imports are written to `shadertoy-imports` inside the `user-scenes`
  folder (`import::imports_dir`). `user-scenes` is found the way a scene
  folder is (`library::resolve`: the current directory, then beside the
  program); where it is not a folder, the one beside the library folder
  is used, and the first import creates it.
- The library lists them through `user-scenes`, which is searched through
  its subfolders (D546). Where `user-scenes` has been removed from
  Settings' scene folders, the imports folder is listed on its own, so an
  import never vanishes from the library.
- A re-import is checked against the imports folder. A shader imported
  into `scenes/` before this change is not found there, so importing it
  again makes a second copy instead of asking to replace it. Move the old
  one by hand.

**Rendered thumbnails.** A scene could get a picture only from its own
`IMAGE_PATH` (D212) or from the operator's "Use frame as picture" (D222).
D222 named what would reopen it: a library with many scenes and no
pictures. The owner asked for a button.

- **The Library's camera button** (beside refresh) queues every scene
  Strobe may write (not inside Synesthesia's install) whose `IMAGE_PATH`
  names no file (`thumbnails::wanting`). Its tooltip shows progress.
- **A finished Shadertoy import** queues its new scene.
- **How a picture is made:** the scene is loaded at 320x180, run for 3 s
  of scene time at 30 frames a second with the live audio, and its last
  frame is written by `snapshot::save`, the same path as D222
  (`thumbnail.jpg`, `IMAGE_PATH` edited in place). Feedback scenes have
  filled in by then. A frame that catches a dull moment can be replaced
  with "Use frame as picture".
- **One scene at a time, 15 frames a step**, so the output keeps drawing
  between steps. A scene's compile still blocks its step, as a
  prerender's does (D542). The job waits while a playlist is loaded, a
  load is pending, the context is being rebuilt or a screenshot is being
  taken. A scene with unsaved Editor edits is skipped.

**Evidence:** unit tests for the imports folder and its fallback listing
(`import`, `app`), and for the queue and which scenes want a picture
(`thumbnails`). Not yet run in the app.
