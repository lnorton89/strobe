# D565: a shared scene's link shows a frame of the scene, sent by the browser that shares it (2026-11-20, owner's request)

**Context.** Every `/s/<id>` link served the `/play` page as it is (D527), so
pasted into a chat or a post it showed the sandbox's own card: the same title
and the same picture whatever the scene. The owner asked for the card to show
the shader.

**Decision.**

- **The picture comes from the sharer's browser.** Only a browser can draw a
  scene: the Worker has no GPU, and rendering on a server would need one and a
  queue. Share already has the frame on screen, and the engine keeps its
  drawing buffer, so `cardFromCanvas` (`site/src/lib/play/card.ts`) copies the
  canvas, crops the largest centred 1200x630 part, and encodes a JPEG, stepping
  its quality down until it is under 160 KB. It goes in the same `POST
  /api/share` as the scene, as `card`.
- **The card is not part of the scene.** It is stored beside it as
  `cards/<id>.jpg` and does not enter the content hash, so a scene's name is
  what it was and old links are unchanged. A scene keeps the first card it
  gets: nothing in the bucket is ever rewritten, which is D527's rule.
- **A bad card is dropped, not refused.** The Worker takes it only if it is
  base64 of a JPEG within the size limit whose frame header says 1200x630:
  `jpegSize` walks the segment markers to the first SOF and reads its height
  and width, without decoding the picture. Anything else (another format, a
  tiny or huge picture, segments that run past the data) is ignored and the
  scene still gets its link. The scene's own 256 KB limit is measured without
  the card.
- **`/s/<id>` rewrites the page's social tags.** `cardPage`
  (`site/worker/share-card.ts`) sets `og:title` and `twitter:title` to the
  scene's title, `og:url` to the link, and, when the scene has a card,
  `og:image`, `twitter:image` and their alt text to `/api/card/<id>.jpg`. It
  is a replacement over the page's text and escapes what it writes. A tag the
  page does not have is left alone, so a changed page falls back to the
  generic card and never breaks; a scene without a card (shared before this,
  or posted without one) keeps the page's picture with its own title.
- **Who can set a card.** Whoever shares a scene first, which is whoever
  could have shared any picture as a scene's `IMAGES` anyway. There is no
  route that adds a card to a scene later, so a visitor cannot change what
  someone else's link shows. Posting the same scene again with a card does
  give a cardless scene its first one.
- **First card wins, and that can be claimed by someone else (accepted).** A
  scene's id is a hash of its content, and its text is public once its link
  is, so anyone can `POST` the same scene with a JPEG of their own before its
  owner does. Every scene shared before cards existed is open to that until
  someone gives it one, and so is any scene whose text is known before it is
  shared. The JPEG must still be a 1200x630 picture, and it is shown only on
  links to that scene; it cannot replace a card that is there. Letting a
  later card replace an earlier one would open every link to the same thing,
  so it is not done. The fix if it is ever abused is the operator's: delete
  `cards/<id>.jpg` (the site README says how), and the next share sets it
  again.

**Cost.** One R2 read and one head on each `/s/<id>` view, and up to 160 KB
stored per shared scene.

**Test.** `tests/unit/share-card.test.ts`: what is read as a card, its size
from the frame header (baseline and progressive, fill bytes, a DHT segment
first) and every other size dropped, the shared byte and pixel limits, first
card kept, the tags rewritten with and without a card,
escaping, a page without the tags, and the crop. Not yet seen on the deployed
site, and no link-preview service has fetched one.

**Would reopen:** cards used to show something other than the scene (then
the Worker renders nothing still, but Share could send a hash the page
checks), or a wish for cards on scenes posted without a browser (then the
first visitor's browser could be asked to fill it in, with the abuse that
invites).
