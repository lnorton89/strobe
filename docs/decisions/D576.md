# D576: Spout's library ships in the release zip, pinned like ANGLE (2026-11-27, v0.5.0 customer report)

**Context.** v0.5.0 shipped Spout output and input (D570–D575), but not
the library they call. `SpoutLibrary.dll` was looked for beside
`strobe.exe` and on `PATH`, and the error said to install Spout from
spout.zeal.co. The first person to try it, a VJ using Resolume Arena, got
that error. Installing Spout did not help: the installer puts down no
`SpoutLibrary.dll`. Every other Spout program they use (Coollab, Tooll3,
NestDrop, Milkwave) carries its Spout library in its own folder, so
turning Spout on just works. Spout is BSD-2-Clause, which allows exactly
that.

The release checks missed it because the development machine had the DLL
beside its builds. The package check and the release-candidate harness
checked ANGLE against the pin, and nothing at all about Spout.

**Decision.**

- **`scripts/native-deps.json` pins a second bundle, `spout`:** Spout
  2.007.018's `Spout-SDK-binaries` release asset (archive SHA-256), the
  64-bit static-runtime (`MT`) `SpoutLibrary.dll` inside it (its path in
  the archive and its SHA-256), and Spout's `LICENSE` from the same tag
  (URL and SHA-256, shipped as `LICENSE.spout.txt`). The MT build needs no
  Visual C++ runtime installed. It is the build D572's vtable slots were
  read against and the one verified in OBS and with a scripted sender
  (D573, D575).
- **`scripts/fetch-angle.ps1` fetches both bundles** and hash-checks every
  file. strobe-gfx's build script counts `SpoutLibrary.dll` among the files
  it needs, so a development build gets it too.
- **The package carries it,** with its licence, and xtask reads every
  bundle (`native::BUNDLES`). The SBOM gains a component for it, and
  `THIRD_PARTY.md` gains a row.
- **The package check now runs the program's own view of it:**
  `strobe --diagnose` gains a `spout` row (the pinned version, another
  build, or missing), and `package-check` fails unless that row says the
  library matches the pin. A zip without it can no longer pass.
- **The messages stop sending people to install Spout.** A missing library
  now means a damaged unpack, and the error says so.

**Consequences.** The zip grows by about 0.5 MB. A Spout bump is one commit
to the manifest, as an ANGLE bump is, but must also re-check D572's vtable
slots against the new header. A development profile that already has
ANGLE gets Spout's library on its next build, because the build script
sees it missing. A later Spout pin change does not refresh it, since the
stamp names only ANGLE's version.
