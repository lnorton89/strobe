# D564: the sandbox plays cube maps and a still MEDIA picture the visitor adds (2026-11-07, backlog W-01, on the owner's go-ahead to keep working)

**Context.** D554 brought `IMAGES` pictures, includes, `textureFinalPass` and
presets to `/play`, and left two of the app's pictures out. A `CUBEMAPS`
entry and a scene's `MEDIA` both read black there, with a note saying they
were app-only. The app loads both from the scene folder, `MEDIA` on a decoder
thread, and the browser has neither a folder nor threads.

**Decision.**

- **The pictures come from the page, as `IMAGES` do.** Add image keeps each
  file under its own name, and now takes several at once, so a cube map's six
  faces are one choice. The sandbox finds every path a scene names by its full
  name, then by its file name: `IMAGES` entries, each `CUBEMAPS` face, and the
  `MEDIA` picture.
- **A cube map goes through the app's own cutting.** `assets::cubemap_from_bytes`
  is `load_cubemap` with the files read from memory: six faces in GL's order or
  one 6:1, 1:6 or 4:3 picture, checked for size and edge, and flipped for a
  `VFLIP` entry as Shadertoy does (D553). `ScenePlayer::replace_cubemap` uploads
  it as the folder's cube is uploaded. A face the page lacks is named under the
  editor with every other missing face, and the cube reads black, as in the app.
- **A still `MEDIA` picture is decoded and uploaded at once.**
  `ScenePlayer::replace_media_still` decodes the bytes as `decode_frame` decodes
  a file (shrunk to 2048 on its long side, flipped upright unless `VFLIP` is
  false) and hands the frame to `Media::still`, which uploads it with the
  entry's wrap and filter and no thread. `syn_MediaType` is 1, as for a still in
  the app.
- **A `MEDIA` folder (an image sequence) still plays only in the app.** A
  sequence is many pictures in name order, decoded in the background and held
  within 192 MiB (D225), which a page that keeps pictures one by one does not
  model. Its note says to add a picture, and that a folder of pictures plays in
  the app only.

**Test.** `assets`' tests: faces from memory are the faces from files, flipped
alike, and a missing face is named; a still from memory is the frame its file
makes. strobe-web's sandbox tests on headless GLES 3.0 (Mesa, run in WSL on
LIGHTNING, and in CI's Linux job), with two fixtures of their own,
`cube-faces` and `media-still`: each draws byte for byte what the app's
`SceneFolder::load` and `ScenePlayer` draw from the folder, and without its
pictures reads black and names what is missing. Playwright
(`play-parity.spec.ts`) adds the six faces in one choice and the still in
Chromium on SwiftShader, and sees the notes go and the picture drawn.

**Would reopen:** a scene that needs its `MEDIA` sequence in the browser, which
would take the page holding a folder's pictures and a budget for them.
