# D551: `--diagnose` raises its box only when nothing reads its output, so a harness run ends (2026-11-05)

**Context.** `cargo xtask rc` passed v0.3.0's archives on LIGHTNING and on
the T480. But a run whose output went through a pipe never ended, on
either machine. On the T480 it waited until a one-hour limit killed it.

Reproduced on LIGHTNING. Once the harness had printed its pass and
exited, the only process left was a hidden PowerShell showing
`--diagnose`'s "Diagnostic report saved to" box, from the harness's
package check. Closing that box ended the pipe at once.

`show_notice` leaves its box up after `strobe.exe` exits, on purpose (T480
Task 50). But Rust starts every child on Windows with handle inheritance
switched on. So the box's PowerShell held every inheritable handle in its
chain, the harness's own output pipe included, and the pipe stayed open
until someone clicked OK. In a harness run, nobody sees the box.

**Decision.**

- **`--diagnose` raises its box only when nothing reads its output.**
  `dialog::stdout_is_read` is true when the process has a standard output
  handle: a console, a pipe or a file. A release `strobe.exe` is a GUI
  program, so started from Explorer, a shortcut or a plain `cmd` prompt
  it has none, and the box is how its report is found. Redirected or
  piped, the printed text is the answer, and no box is raised.
- **The harness needs no change.** Its package check reads `--diagnose`'s
  output, so the box is not raised there any more.
- Other boxes are unchanged. `show_error` waits on its box, so the box
  closes with its process. Every run the harness makes is `--screenshot`,
  which is unattended (no boxes at all).

**Trade-off.** Starting a child with only its own handles (Windows'
handle list) would fix this for any box. Stable Rust does not expose it,
and the D541 rules keep `unsafe` out of strobe-app. So the fix is to raise
no box where it can do harm, not to stop handles being inherited.

**Test.**
- `dialog` test `a_test_run_has_an_output_someone_reads`: a captured
  stdout counts as read.
- On LIGHTNING, `cargo xtask rc` through a pipe, on a `release-fast`
  package of this change: the pipe closed when the harness exited, and no
  box was left. Recorded in `hardware/AMD.md`.

**Would reopen:** stable Rust gaining a way to pass a child only the
handles it needs, which would let a box outlive its process safely.
