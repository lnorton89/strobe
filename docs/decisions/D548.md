# D548: a release waits in draft for the owner's approval, so its own archives are checked on a GPU first (2026-11-04, owner's choice)

**Context.** CONTRIBUTING said to run the draft's own archive through
`cargo xtask rc` (D537) before publishing. But `release.yml` uploaded the
archives and undrafted the release in one step, as soon as the build and
CI on the tagged commit passed (D521). So nobody could test the draft's
exact zip before it went public. The candidate checked on the T480 was
built there from the same commit, which proves the source, not the
published bytes. The owner chose an approval gate over testing a local
build before tagging.

**Decision.**

- **`publish` is split in two.**
  - `stage` does everything the old job did except undraft: it downloads
    the build, attests provenance and the SBOM, and uploads every file to
    the draft. It writes the commands to test the draft into the run's
    summary.
  - `publish` only undrafts. It runs in a `release` environment that needs
    the owner's approval, and it checks the release is still a draft.
- **The `release` environment** has the owner (lnorton89) as its required
  reviewer, self-review allowed, and a deployment policy that admits `v*`
  tags only. It lives in the repository's settings, not in a file.
- **The order** is in CONTRIBUTING:
  1. tag;
  2. the draft is staged;
  3. on the T480 or the mini PC, `gh release download <tag> --pattern
     "strobe-*.zip"` then `cargo xtask rc` on those two files;
  4. approve `publish`, or reject it and the release stays a draft.

**Trade-off.**
- A release now needs a person at a Windows machine with a GPU before it
  is public. That was always the documented intent, but now a release
  waits for it.
- An unapproved run expires after GitHub's 30-day limit. The draft stays,
  and re-running the workflow resumes it (D521).

**Test.** The next release is the first run through the gate. Until then:
the job graph is `actionlint`-checked in CI, and the environment's
protection rules were read back from the API (required reviewer
lnorton89, branch policy `v*` tags).

**Would reopen:** a release that must go out with no GPU machine to hand.
That would mean approving without the harness, which the gate allows, at
the owner's discretion.
