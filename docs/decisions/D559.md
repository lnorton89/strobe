# D559: /play rebuilds its engine when the WebGL context comes back (2026-11-06, backlog W-02, on the owner's go-ahead to keep working)

**Context.** A browser can take a page's WebGL context at any time: a driver
reset, a phone putting the tab away, too many contexts open. Backlog W-02 asks
for recovery without a reload. `/play` did not listen for it, so the picture
stayed dead while the page looked alive, and a compile in that state reported
a shader error the scene did not have.

**Decision.**

- **A new engine on the context that comes back,** rather than re-creating GL
  objects inside the old one. Nothing the engine holds on the GPU survives, and
  building it is what already makes all of it. No code in `strobe-web` or
  `strobe-gfx` changes, and the desktop app, which has its own reset path (R-07),
  is not touched.
- **The page calls `preventDefault` on `webglcontextlost`.** Without it the
  browser never offers the context back.
- **While the context is gone** the frame loop, compiles, resizes and Generate
  controls wait, and the picture says so. An edit is kept and compiled on the way
  back. A person is told to reload only if the message stays.
- **The last scene that compiled goes first,** then the editor's if it differs.
  A broken edit keeps its error and the last good picture, which is the
  sandbox's promise for any failed compile.
- **What comes back:** the scene, control values, the clock and the audio source.
  **What does not:** the contents of feedback buffers, which restart, and a
  script's state, since `setup()` runs again. Neither is held anywhere but the
  lost context and the terminated worker.
- **A run of Generate controls stops** with a message, as an edit stops it. A
  review open at the time stays, since accepting needs no GPU.

**Trade-off.** A feedback scene visibly restarts, where saving its textures
every frame to restore them would cost far more than the rare loss is worth.

**Test.** `site/tests/e2e/play-context.spec.ts`, using `WEBGL_lose_context` in
Chromium on SwiftShader: the picture and a moved control return, a second loss
recovers too, a broken edit keeps its error and picture, a run stops and can run
again, an open review can be accepted, and a scripted scene's script runs again.
Run once by hand on an RX 580 through ANGLE-D3D11 with `12-silicon-atlas`: back
in about 0.1 s of page time, at 60 fps, with no page errors. Not yet seen: a real
driver reset, or a phone putting the tab away (W-02).

**Would reopen:** a browser that restores a context the engine cannot rebuild
on, or a feedback scene where the restart is a real problem.
