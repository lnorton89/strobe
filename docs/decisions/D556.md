# D556: the computer and display stay awake while the output is fullscreen (2026-11-05, owner's request)

**Context.** A show runs for hours with nobody touching the keyboard or
mouse. Windows' idle timeouts can then turn the display off, start the
screen saver or put the machine to sleep, mid-set and on the projector.
Nothing in Strobe asked Windows not to. The owner asked for a way to
enforce it.

**Decision.**

- **While the output window is fullscreen, Strobe holds a power request**
  that keeps the system out of idle sleep and the display on, with the
  screen saver held off: `SetThreadExecutionState(ES_CONTINUOUS |
  ES_SYSTEM_REQUIRED | ES_DISPLAY_REQUIRED)`. It lets the request go when
  the output leaves fullscreen or Strobe exits, and the machine's own power
  settings apply again.
- **Fullscreen is the signal**, checked once a control-window frame
  (`awake::KeepAwake::follow`). It is how the output goes on a projector:
  by command, F11, a layout, a venue autostart or the command line. So
  every path is covered, and an unchanged state costs nothing. No setting:
  a fullscreen show that sleeps is never wanted, and a windowed output
  leaves the machine's settings alone.
- **The call lives in `strobe-diag/src/native.rs`**, beside the crash
  handler's leaf, under the same rules: one private safe function, one
  `unsafe` call, a `SAFETY` comment. `strobe_diag::power::AwakeRequest` is
  the safe guard, `!Send` because the request belongs to the thread that
  made it. The app's main thread runs the event loop for the whole run.
- **`windows-sys` 0.61, already in the build** through egui-winit and rfd,
  with its `Win32_System_Power` feature. The `keepawake` crate was tried
  first. It would have avoided the leaf, but its Linux half put a D-Bus
  stack into `Cargo.lock` (`zbus`, with three crates cargo-deny flags as
  unmaintained), so it was dropped.
- **A refusal is logged once** and not asked again until the output next
  goes fullscreen.
- **Windows only.** macOS (IOKit) and Linux (systemd-inhibit over D-Bus)
  wait for their releases (R-08, G-07). There `AwakeRequest::new` says it
  is not available, and the log says so once.

**Trade-off.** One more native call in the workspace's two unsafe files.
A machine whose output is fullscreen by mistake stays awake until it
leaves fullscreen.

**Test.**
- `awake` tests: the request is made once on entering fullscreen, released
  on leaving, made again on returning, and a refusal is not retried every
  frame.
- `power` test (Windows): a request is granted and released twice.
- Still to see on the show machine: `powercfg /requests` lists Strobe under
  DISPLAY and SYSTEM while the output is fullscreen, and nothing once it
  is windowed.

**Would reopen:** a venue that wants a fullscreen output to sleep anyway
(a setting then), or the macOS and Linux releases.
