# D538: the library lists other scene folders where they are, and the watched folder is gone (2026-11-03, owner's request)

The watched drop folder (D240, D265) copied scenes that arrived in a
folder into the library, and left alone whatever was there when watching
started. Pointed at `user-scenes/` (D532), it did nothing for the scenes
already in it, and would have copied friends' unlicensed scenes into
`scenes/`, which git tracks. The owner asked for it to go, and for a list
of extra scene folders instead.

- **Settings > Library > Scene folders.** One row per folder, with the
  app's line saying how many scenes it lists or why none (a folder that
  has gone: "Not found"), and *Remove*. Then a path, *Browse...* and
  *Add*. Both act at once and list the library again; the pane only asks
  (`Action::AddSceneFolder`, `Action::RemoveSceneFolder`).
- **Listed where they are, not copied.** A folder's scenes come after the
  library folder's own and before Synesthesia's, as `Source::Folder`:
  writable like the library's, so the Editor, tags and presets change
  them in place. A scene already listed is not listed twice, and the
  library folder itself is never one of them.
- **`user-scenes` by default.** `ui.toml`'s `[scene_folders] folders`
  starts as `["user-scenes"]`, found as `--library` is (the current
  folder, then beside the program). A list the person empties stays empty.
  A missing folder costs nothing but its line in Settings.
- **Add checks; launch does not refuse.** Add refuses an empty field, a
  path that is not a folder, the library folder, and a folder listed
  already, with one sentence under the field. A saved folder that is gone
  at launch stays in the list, shown as not found, so a drive plugged in
  later lists again after any rescan.
- **Removed:** `intake::Inbox`, `--watch-folder`, the `[watch]` table in
  `ui.toml` (an old file's is ignored), and Settings' watched-folder
  group. Dropping a scene, or a folder of scenes, on the window still
  copies into the library (D218, D235).

**Evidence:** `app` test
`settings_adds_a_scene_folder_once_and_refuses_the_library_and_typos`,
`intake` test `a_scene_folder_must_exist_and_not_be_the_library`,
`ui::settings` test `add_and_remove_ask_the_app_and_change_nothing_themselves`,
`ui::state` test `the_scene_folders_are_saved_and_reread_but_the_add_field_is_not`,
the `prefs` round trip and missing-field tests, and the shell scenarios
"settings with scene folders" and "settings with a refused scene folder"
at every size.

**Would reopen:** wanting a folder searched deeper than one level, or a
folder's scenes marked as coming from it in the browser.
