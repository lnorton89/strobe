# D543: launch opens on the Library view (2026-11-03, owner's request)

The main view at launch was whatever the saved layout last showed, often
the bare live preview. The owner wants the app to open on the Library.

- At launch the Library pane is opened after the saved layout is read, so
  it is the newest main pane and is shown (the main view is the newest
  open main pane). The side panel and widths stay as saved.
- `--no-panes` and `--open-pane` are applied after it, so a command line
  that asks for another view, or none, still gets it.
- **The Editor no longer raises itself.** A layout that keeps the Editor
  open behind another view has it filled with the playing scene on the
  first frame; that fill went through `open_editor`, which also brought
  the Editor to the front, so it took the main view from the Library. The
  fill (`edit_scene(None, false)`) now loads the scene without raising
  the pane; *Open in Editor* still raises it.
- During a run, the rail chooses the view as before; only launch is
  changed.

**Evidence:** on LIGHTNING, with a saved layout whose newest pane was the
Editor: before the Editor fix, a launch saved the pane order with
`editor` newest (it raised itself after the Library was opened); after
it, `browser` is newest, so the Library is the view shown.

**Would reopen:** wanting the last view back for some workflow, which
would make this a setting.
