# D569: the site's `npm ci` skips `onnxruntime-node`'s CUDA download (2026-11-26)

**Context.** `@huggingface/transformers` 3.8.1, a dev dependency of the
site for the CLIP scripts (`clip-concepts.mjs`, `copy-clip.mjs`), pins
`onnxruntime-node` 1.21.0. Its install script downloads the CUDA execution
provider, `onnxruntime-linux-x64-gpu-1.21.0.tgz`, from ONNX Runtime's GitHub
release on every Linux x64 install unless told not to, because those
binaries are too large for the npm package. That download now answers
404, so `npm ci` fails and CI's `site` job (D552) has failed on every pull
request since. Nothing in the site runs ONNX on a GPU: the browser uses
`onnxruntime-web`, and the Node scripts run on the CPU binaries the package
bundles.

**Decision.** The `site` lane's `npm ci` step sets
`ONNXRUNTIME_NODE_INSTALL_CUDA=skip`, the variable the install script reads
(the same switch as its `--onnxruntime-node-install-cuda=skip` flag), so the
CUDA binaries are never fetched. It lives in `crates/xtask/src/ci.rs`, so CI
and `cargo xtask ci site` on a desk behave the same. It is not put in
`site/.npmrc`: npm 11 warns on keys it does not know there, and its docs say
a later major version will reject them. `site/README.md` gives the variable
for a direct `npm install` on Linux.

**Would reopen:** a site script that needs the CUDA provider, or a
`@huggingface/transformers` release whose `onnxruntime-node` no longer
downloads anything at install, which makes the variable dead.
