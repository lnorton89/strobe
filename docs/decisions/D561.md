# D561: Claude Code reviews PRs on the owner's Max plan, with the job's own token (2026-11-07, owner's request)

**Context.** The owner has a Claude Max plan; API credits are billed apart
from it. Pull requests had no automated review beyond CI.

**Decision.**
- `claude-review.yml` runs `anthropics/claude-code-action` once per PR (on
  open, reopen and leaving draft), with a prompt built from CLAUDE.md's
  rules. Pushes to an open PR do not re-run it, so a busy agent branch does
  not spend the plan's usage; `@claude` asks for another pass.
- `claude.yml` answers `@claude` in comments, reviews and new issues, and
  only for the owner, members and collaborators: the repository is public,
  and anyone else's mention would spend the owner's plan.
- Both authenticate to Claude with `CLAUDE_CODE_OAUTH_TOKEN` (from
  `claude setup-token`, tied to the Max plan), not an API key.
- Both pass `github_token: ${{ github.token }}` instead of the Claude GitHub
  App's token, so neither depends on which repositories the App is
  installed on. The cost: comments come from github-actions[bot], and
  GitHub starts no workflow for a push made with that token, so CI does not
  run on commits Claude pushes from `claude.yml`.
- Fork PRs are skipped: `pull_request` gives them no secrets.

**Would reopen:** wanting CI on Claude's own pushes (switch to the App's
token), or review usage outgrowing the plan (move to API credits).
