# D562: Scenes from a photo are made by one written pipeline: a project skill, the strobe-forge checker and its LLM loop (2026-11-07, owner's request)

**Context.** The owner asked for scenes made from eight photos of a friend's
artwork, and for the occasion to be used to make shader creation from an image
reproducible: an LLM pipeline with skills, and possibly a Rust one with an LLM.
The image scenes in `user-scenes/` were each made by a fresh conversation
re-deriving the same method, and the case studies behind D560 found most
iteration went on rediscovering the same fixes (clipped halos, heroes too
small, strokes too thin, neon look), and that the LLM once passed a render the
owner rejected.

**Decision.**

- **The method is a project skill**, `.claude/skills/scene-from-image/`: the
  reading to write down first, the archetypes, a template scene that already
  holds the clock pass, halo-safe paint, analytic pixel size and the tone
  shoulder, the control and audio conventions, a critique checklist built from
  past rejections, and the gates. Any agent, or a person, follows the same
  steps, and the reading is kept as the scene's header comment.
- **One checker for every route**, `strobe-forge check`: frames at fixed times
  with the bench's deterministic audio, a sheet with the reference beside
  them, both GLSL dialects, timing at 1080p, the From image gates (black,
  flat, blown, frozen, flashing) and every control at its extremes. The skill,
  the LLM loop and a person read the same report.
- **The Rust LLM loop**, `strobe-forge make`, drives the same skill text and
  checker through a provider trait with Anthropic as the first provider: the
  photo and the skill go in, two files come out, compile errors go back up to
  three times, then the sheet goes back for critique. The model gets no tools
  and its reply can only become one `main.glsl` and one `scene.json`, as in
  D560. The key comes from the environment and is never written anywhere.
- **Privacy stays as it was.** Photos and their scenes live in the gitignored
  `user-scenes/`; the skill says so, and `make` says it sends the photo to the
  provider (D526, D532). Generated scenes carry no licence stamp.
- **A person still accepts.** The checker narrows; the owner's eye decides.

**Rejected.**

- *Only a Claude Code skill:* it would leave no route without an agent session,
  and nothing to run in a script or later in the app.
- *Only the Rust loop:* the interactive route, where an agent can crop, zoom
  and look between rounds, made every scene so far.
- *Fine-tuning or a local model:* no data set, and the free tiers do not reach.

**Consequences.** `strobe-forge` joins the tooling layer beside `strobe-bench`.
Its open work, real provider runs and more providers, is in the backlog.
